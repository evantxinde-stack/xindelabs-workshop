Modul 1 · Mindset

Identify. Adapt. Automate.

IDENTIFY · ADAPT · AUTOMATE
  • Identifikasi workflow kerja kamu — mana yang berulang dan bisa diimplementasikan ke AI.
  • Adaptasikan workflow itu jadi step-by-step yang nantinya digantikan AI Agent.
  • Automatiskan yang perlu, minta persetujuan untuk yang penting.
TRIAL · ERROR · EVALUATE
  • Berani mencoba walaupun awalnya berantakan — nggak masalah.
  • Kalau ada error, pakai reverse engineer buat identifikasi errornya di mana.
  • Evaluasi setiap workflow, test sampai 100% sesuai keinginan kamu.
EXPERIMENT
  • Experiment dengan batasan — supaya data-data kamu tetap aman.
  • Mulai dari scope kecil, jangan langsung semua.
  • Yang penting: jalan dulu, sempurna belakangan.

Mindset ini fondasi semua modul berikutnya — lo jadi arsitek, bukan tukang.

Modul 2 · Intro to AI Agents

Agent vs Chatbot.

🤖 AI Agent

  • Bersifat proaktif-otonom
  • Mampu merencanakan langkah sendiri
  • Menjalankan tool eksternal
  • Memantau hasil eksekusi
  • Mengulang eksekusi kalau terjadi error

💬 Chatbot

  • Bersifat pasif-reaktif
  • Hanya merespons prompt
  • Kerjanya dalam satu sesi teks saja
  • Nggak punya rencana sendiri
  • Nggak bisa jalan tanpa kamu ketik
Modul 2 · Lanjutan

AI Harness & AI Automation.

AI HARNESS "Tali pengaman" buat AI

Harness = lapisan yang ngatur cara AI berpikir & bertindak. Dia yang kasih aturan, tool, dan batasan — supaya agent nggak ngawur. Hermes Agent itu harness-nya.

AI AUTOMATION Dari "bisa" jadi "jalan sendiri"

Automation = waktu agent udah bisa mikir + punya tool, tugas itu dijalankan otomatis tanpa kamu ketik ulang. Trigger, jadwal, event — agent yang handle.

Harness tanpa automation = pintar tapi nunggu. Automation tanpa harness = jalan tapi ngawur. Butuh dua-duanya.

Modul 3 · Introduction to Hermes

Hermes: framework autonomous agent open-source.

Dikembangkan oleh Nous Research. Sebuah orkestrator antar program lewat LLM — jadi bisa melakukan aksi nyata, bukan cuma membalas chat.

WHY 01

Agent that grow with you — belajar dari pola kerja kamu dan selalu update.

WHY 02

Memory persisten + auto-generate skills. Nggak pernah lupa cara nyelesain masalah.

WHY 03

Komunitas tumbuh — sudah dilengkapi Skill Hub & Plugin Hub.

Modul 3 · Infrastruktur

Cloud/VPS vs Lokal.

☁️ Cloud / Virtual Private Server

Pros
  • Aktif 24/7 tanpa mati
  • Server stabil, nggak pernah tidur
  • Nggak perlu dibawa-bawa
  • Tugas yang udah di-set beneran dieksekusi
Cons
  • Sewa bulanan
  • Kalau salah setting keamanan bisa bocor
  • Datanya milik server, bukan pribadi

💻 Lokal / Mac Mini, Laptop

Pros
  • Biaya tambahan hampir nol
  • Data milik pribadi, mudah diawasi & dimatikan
  • Pas untuk belajar
Cons
  • Laptop ketutup / server mati = agent OFF
  • Kinerja tergantung spek laptop kamu

Lokal buat latihan & eksperimen. Cloud buat agent yang harus jalan 24/7.

Modul 5 · Give Your Agent Life

SOUL.md — kepribadian agent kamu.

Hermes punya profile yang disebut SOUL.md: jati diri, gaya, kepribadian, dan karakter sang agent.

KEPRIBADIAN

Mau agent punya kepribadian seperti siapa? Contoh: Engineering, CEO. Value apa yang mau kamu tanamkan.

GAYA

Cara berbicara: santai, formal, ala jaksel, to the point. Atur sesuai kamu — atau dia menyesuaikan sendiri.

LARANGAN

Jelaskan apa yang tidak boleh dilanggar oleh sang agent.

TEKNIS

Gimana agent menangani hal teknis. Contoh: fokus yang simpel dulu, baru yang ribet.

Agent tanpa SOUL.md = robot generik. Agent dengan SOUL.md = asisten yang punya karakter.

Modul 6 · Lanjutan

Kanban, Worker, & Swarm.

Antrean permanen (~/.hermes/kanban.db) biar banyak Profile bisa kerja estafet. Enam kolom status:

Triage→ Todo→ Ready→ In Progress→ Blocked→ Done
DI BALIK PAPAN — DISPATCHER

Mesin bernama Dispatcher berjalan otomatis di dalam Hermes Gateway setiap 60 detik. Tugasnya: cek kolom Ready, lalu otomatis "membangunkan" Profile yang ditugaskan pada kartu itu untuk mulai bekerja.

⚠ Kalau Gateway mati, kartu di Kanban tidak akan jalan.

ORCHESTRATOR — SI PEMBAGI TUGAS

Di Kanban ia jadi Decomposer: baca daftar Profile + deskripsi keahliannya, pecah ide mentah jadi kartu anak via kanban_create, lalu ikat urutannya via kanban_link.

Di chat langsung, ia pakai delegate_task buat manggil sub-agen di belakang layar.

Modul 8 · Loop Engineering

Biar agent memperbaiki diri sendiri.

Loop Engineering merancang bagaimana agen berpikir, bertindak, mengevaluasi hasil, dan memperbaiki diri secara berulang sampai tujuan tercapai.

REASON-ACT-OBSERVE

Siklus dasar: agent menganalisis situasi (reason), memanggil tool eksternal (act), lalu baca data hasilnya (observe) buat nentuin langkah berikutnya.

TERMINATION CRITERIA

Aturan ketat kapan loop harus berhenti — karena tugas selesai, atau batas toleransi tercapai.

SELF-CORRECTION

Saat eksekusi gagal, log error dikembalikan ke model supaya sistem revisi parameternya sendiri — bukan langsung berhenti atau macet.

CIRCUIT BREAKERS

Pembatasan deterministik: max_steps, batas token, atau waktu tunggu — biar nggak terjebak infinite loop yang boros.

Komponen 1 · Profile

Profile — fondasi & identitas agen.

Profile adalah folder rumah terpisah (~/.hermes/profiles/nama_profile/) yang menyimpan seluruh pengaturan dan ingatan satu agen.

SOUL.md

Karakter, instruksi peran, dan batasan kerja agen tersebut.

config.yaml & .env

Pilihan model AI (coder pakai model kuat, researcher pakai yang hemat), API key, daftar tools & skills.

state.db & memories/

Riwayat obrolan dan ingatan jangka panjang yang dipelajari dari sesi sebelumnya.

⚠ ATURAN PENTING

Jangan pernah menjalankan dua agen di satu Profile yang sama secara bersamaan — memori mereka akan saling timpa. Butuh peran berbeda? Wajib buat Profile baru:

hermes profile create researcher --description "Riset data web, baca dokumentasi, dan tulis rangkuman fakta."

Parameter --description sangat penting — ini yang dibaca Orchestrator saat membagi tugas di Kanban.

Komponen 2 · Bot

Bot — pintu ngobrol ke Profile.

🖥️ Bot Mode (Desktop)

  • Profile yang dipasang ke daftar kontak di menu Bot Mode Hermes Desktop
  • Lengkap dengan avatar dan ruang chat tetap
  • Semua Bot adalah Profile, tapi tidak semua Profile jadi Bot — ada yang kerja di belakang layar lewat Kanban

💬 Messaging Bot

  • Akun bot di platform luar: Telegram / WhatsApp / Discord / Slack
  • Dihubungkan ke satu Profile lewat Hermes Gateway
Aturan Penting
  • Satu token bot (mis. satu TELEGRAM_BOT_TOKEN) hanya boleh dipakai satu Profile — biar nggak berebut pesan (long-poll conflict)
Komponen 3 · Kanban

Kanban — papan kerja multi-agen.

Antrean kerja permanen (~/.hermes/kanban.db) yang memungkinkan banyak Profile bekerja sama secara estafet. Enam kolom status dari kiri ke kanan:

Triage→ Todo→ Ready→ In Progress→ Blocked→ Done
DI BALIK PAPAN — DISPATCHER

Mesin bernama Dispatcher berjalan otomatis di dalam Hermes Gateway setiap 60 detik. Tugasnya: cek kolom Ready, lalu otomatis "membangunkan" Profile yang ditugaskan pada kartu itu untuk mulai bekerja.

⚠ Kalau Gateway mati, kartu di Kanban tidak akan jalan.

Komponen 4 · Orchestrator

Orchestrator — si pembagi tugas.

Otak yang mengatur strategi. Bekerja dalam dua cara:

DI KANBAN Auto / Manual Decomposer
  • Kamu lempar satu ide mentah ke kolom Triage
  • Decomposer (kanban.orchestrator_profile) baca daftar semua Profile kamu + deskripsi keahliannya
  • Ia pecah jadi kartu anak via kanban_create
  • Lalu ikat urutannya via kanban_link — Tugas B baru boleh jalan kalau Tugas A sudah Done
DI CHAT LANGSUNG delegate_task
  • Saat kamu sedang chatting dengan satu agen
  • Agen itu memanggil sub-agen di belakang layar
  • Buat bantuin jawab pertanyaanmu saat itu juga
Triage ──▶ [kartu anak A] ──▶ [kartu anak B] (Blocked sampai A Done)
Komponen 5 · Worker

Worker — dua kasta yang wajib kamu bedakan.

AspekKanban WorkerSubagent Worker
IdentitasPakai Profile bernama — punya memori & skill tetapAnonim — pekerja sementara, selesai langsung hilang
Cara kerjaFire-and-forget — jalan mandiri di background via DispatcherAgen induk harus nungguin (blocking) sampai subagent selesai
KetahananTahan banting — kalau crash atau butuh input manusia (Blocked), bisa dilanjut lagiSekali jalan — kalau gagal atau sesi ditutup, progresnya hilang
Kapan dipakaiTugas besar, lintas-peran, butuh review manusia, atau jalan berjam-jamTugas singkat (2–5 menit) buat cari info paralel di tengah sesi chat

Uniknya, keduanya bisa digabung: Kanban Worker yang sedang mengerjakan kartunya boleh memanggil Subagent Worker via delegate_task untuk bantu bagian kecil.

Komponen 6 · Swarm

Swarm — empat lapis keroyokan otomatis.

Kalau kamu malas merangkai kartu Kanban satu per satu untuk tugas riset atau analisis paralel, panggil hermes kanban swarm atau /swarm. Hermes langsung mencetak alur kerja otomatis:

Lapis 1
Root / Blackboard CardKartu induk tempat menaruh brief utama dan folder kerja bersama (shared workspace).
Lapis 2
N Parallel WorkersBeberapa Worker langsung jalan serentak mengerjakan sub-topik masing-masing.
Lapis 3
Gated VerifierSatu agen pemeriksa menunggu di kolom Todo sampai semua Worker paralel selesai — lalu cek kualitas & kebenaran hasilnya.
Lapis 4
Gated SynthesizerAgen perangkum akhir yang baru jalan setelah lolos Verifier — menyatukan semua temuan jadi satu laporan rapi.
Rekomendasi · Pilih Sesuai Kebutuhan

Tiga level setup, dari simpel ke agency.

LEVEL 1 · PALING SIMPEL Single Assistant + Subagents

Cocok buat: pemakaian harian — 1 asisten utama di Telegram/Desktop, tapi bisa nyuruh subagent cari data barengan saat chatting.

  • Cukup 1 Profile (default) + 1 Bot
  • Tidak perlu menyalakan Kanban
  • Kerja paralel otomatis pakai delegate_task
LEVEL 2 · PISAH OTAK & KONTEKS Multi-Bot Spesialis

Cocok buat: kamu dengan beberapa topi pekerjaan berbeda (Coding, Copywriting, Riset) — dan nggak mau ingatan/gaya bahasa tercampur.

  • Buat beberapa Profile: hermes profile create coder
  • Atur SOUL.md & model AI spesifik tiap Profile
  • Munculkan masing-masing sebagai Bot terpisah
LEVEL 3 · AUTONOMOUS AGENCY Profile + Kanban + Orchestrator + Swarm

Cocok buat: mendelegasikan proyek besar dari satu pintu, lalu tim agen bekerja estafet di background sampai tuntas.

  • Buat Profile tim + deskripsi keahliannya
  • Aktifkan Kanban di Profile Director
  • Inisialisasi Kanban & nyalakan Gateway
  • Pantau lewat hermes dashboard
Level 3 · Urutan Setup

Empat langkah menuju agency.

LANGKAH 1 · BUAT PROFILE TIM
hermes profile create director --description "Orchestrator utama yang memecah proyek, membagi tugas di Kanban, dan me-review hasil akhir." hermes profile create researcher --description "Spesialis riset mendalam dari web, jurnal, dan dokumen referensi." hermes profile create writer --description "Spesialis penulisan naskah, copywriting, dan dokumentasi terstruktur." hermes profile create coder --description "Spesialis full-stack developer untuk menulis kode, testing, dan git worktree."
LANGKAH 2 · AKTIFKAN KANBAN DI DIRECTOR
hermes -p director tools enable kanban hermes -p director tools enable kanban --platform telegram
LANGKAH 3 · INIT & NYALAKAN GATEWAY
hermes kanban init hermes gateway start

⚠ Wajib diingat: Dispatcher yang membangunkan Kanban Worker hidup di dalam Gateway. Kalau Gateway mati, kartu tidak jalan.

LANGKAH 4 · PANTAU DASHBOARD

hermes dashboard → buka http://127.0.0.1:9119, klik menu Kanban di kiri. Kamu bisa lihat langsung pergerakan kartu dari Triage sampai Done beserta jalur kerja tiap Worker.
